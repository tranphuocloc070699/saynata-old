# System map

Every part of Saynata, its stack and what it does, in detail. CLAUDE.md has the short version and links here.
When a change adds a part, changes the stack or a model, or changes a command, update this page in the same commit.

| Part | Stack | Job |
|---|---|---|
| `EnglishTranslation/` | SwiftUI, iOS 18 | The app, plus two extensions that show the same explain sheet for selected text: `ShareExtension` (Share, then Saynata) and `TranslationExtension` (the system Translate item, when Saynata is the default translation app, iOS 18.4+). Both compile the app folder, see doc-10. Talks only to our backend (the direct LLM clients were removed in TASK-18). **Accounts (TASK-70, `Account/`):** sign in with an email code, tokens in the Keychain; on iOS also an emailed link (opens the app with `saynata://sign-in`), Sign in with Apple (paid account only) and Google (no SDK: `webAuthenticationSession` + PKCE, `GoogleIOSClientID` in Info.plist) (TASK-92, doc-17); a sign-in sheet when the backend says `sign_in_required` (TASK-96: an animated pixel-art cat room on top, then Apple and Google pills and "Use email instead"; the cat pictures are a **paid pack kept out of git**: `scripts/install-cat-assets.sh` copies them into `EnglishTranslation/PaidAssets/Cats/` (git-ignored) and a build phase puts them in the app, a still cat symbol shows without them; `CatSpriteView` animates them with Core Animation only, doc-17); the extensions share the app's sign-in through the App Group Keychain (doc-17); `Speech/` reads English aloud on device with `AVSpeechSynthesizer`. **Explain copied text (TASK-87, `Intents/`, doc-21):** an App Intent and App Shortcut for Back Tap and the Action Button that opens the app; the main screen pastes the copied text and explains it, or empties the input and gives it the keyboard (`CopiedTextLaunch`, `TranslationStore.startFromClipboard`). **Quick explain (TASK-90, `QuickExplainIntent`, doc-21):** an App Intent that stays over the current app (a full-screen video too): iOS asks for the text in its own box, and a short snippet card (`QuickExplainCard`, colors as numbers in `Theme.SnippetColors`) shows the meaning. App target only. **Language line (TASK-106.3, `LanguageLines`, doc-5):** the folded language row of a word card (and the Quick explain card) shows the line from `POST /api/translate-lines`, asked once for every sense when a row opens (guest: `cachedOnly=true`); fallback is the dictionary text (Vietnamese) or Apple Translation. **Sentence result (TASK-89.2, `Views/Sentence/`, doc-4):** one `SentenceCard` with the original and its simple summary (`explanation.meaning`; prompt v9, TASK-89.3: one line, or a gist line and up to 3 `- ` bullets with `**bold**` key words, shown without markers by `SummaryMarkup`; the extension uses `shared/summary.ts`), the target language folded last; every word is tappable (dotted underline, opens the word sheet) and a selected part opens a popup under it that explains the part (`SentencePartStore`, same stream as a sentence). The popup needs a `UITextView` wrapper, so it is iOS only; the Mac has tappable words and the normal selection menu. **Better way to say it (TASK-110, prompt v11):** the same sentence call returns `better` and `betterWhy` (null when the text is natural or over 40 words; the backend `BetterCheck` drops a fix that changes nothing or rewrites too much); a closed folded row between the summary and the language row shows the fix with changed words in bold (`BetterDiff`), only for typed text (`TranslationStore.useTextFromElsewhere` marks copied, shared and Mac Services text); the web card shows it too, the extension never. **History and Liked (TASK-93.2, `History/`, `Views/History/`, doc-22):** a clock button opens a sheet with History (every final word, phrase and sentence, on the device in an App Group SQLite file, newest 1000) and Liked (a star on the word header and sentence card; `/api/liked` per account, a copy on the phone; a guest gets the sign-in sheet). |
| `EnglishTranslation/SaynataMac/` | SwiftUI + AppKit, macOS 15 | The Mac app (F6, TASK-85): a menu-bar icon with a popover, no Dock icon; ⌥⇧Space opens a Spotlight-style floating panel (KeyboardShortcuts package) or Services → Explain with Saynata; open at login with `SMAppService`. The `SaynataMac` target compiles the iOS app folder too (like the extensions), so models, network, stores and result views are shared; the few UIKit/AppKit differences live in `Platform/PlatformSupport.swift` and `#if os(...)` blocks. Build and run the `SaynataMac` scheme on "My Mac" (free Apple ID: Sign to Run Locally). |
| `backend/` | Spring Boot 4, Java 17, Postgres, Flyway, `deepseek-v4.1-flash` through the STEYG gateway (Anthropic-compatible: `CLAUDE_BASE_URL`, `CLAUDE_AUTH_TOKEN`, `CLAUDE_MODEL=deepseek-v4.1-flash`, doc-11; the JSON Schema goes in the prompt and the answer is parsed from the text; doc-7 10-20). Claude Haiku 5.5 on the Anthropic API is only the fallback when no gateway is set | `POST /api/translations`, `POST /api/translations/stream` (server-sent events: `meaning-delta` events make the meaning grow word by word, then `meaning`, then `done`; doc-4), `GET /api/words/{word}`, with a shared cache-first DB. Words not on the bundled SCOWL/NGSL word list are rejected before Claude is called. `/api/admin/**` (Spring Security, ADMIN login in an HttpOnly cookie, `users` table) lets the admin web app list, edit, review and delete words and sentences, see doc-13. **Postgres is the source of truth for the bundled dictionary too** (tables `dictionary_word`, `dictionary_sense`, `dictionary_form`, `media`; Flyway V6): the admin lists and edits bundled words next to the words Claude wrote (ids `b-12` / `w-45`, filters `source`, `cefr` and `media`). The bundled entry wins: `GET /api/words/{word}` answers a bundled word from Postgres and never calls Claude or saves a `word_lookup` row for it (Flyway V9 removed the old duplicates). Media files stay on disk (`MEDIA_DIR`, a Docker volume that Caddy serves at `/media/`), only their rows are in Postgres. A new backend word gets a Pixabay photo or clip in the background (not a word saved by the prefill job) (ffmpeg, `PIXABAY_API_KEY`, Flyway V7); `imageUrl` in `GET /api/words/{word}` is its address (doc-5, doc-11). **Accounts and limits (doc-17):** app users sign in with an email code (`/api/auth/*`, `/api/me`, mail through Resend (AWS SES as an option), `users` + `email_login_code` + `refresh_token`, Bearer access token; Flyway V10), an emailed link (`/api/auth/email-link`, page `GET /auth/link`, `PUBLIC_BASE_URL`), or a Google / Apple ID token checked against the provider's JWKS (`/api/auth/google`, `/apple`, `GOOGLE_CLIENT_IDS`, `APPLE_CLIENT_IDS`; `user_identity`, `email_login_link`, Flyway V22; TASK-92). No domain is in the code; doc-11 section 13 lists what changes when the domain moves. A guest gets only cached and bundled answers; a new Claude call needs a signed-in user (401 `sign_in_required`; `REQUIRE_SIGN_IN=false` lets guests make new calls until the app with sign-in is released, still capped by the budget and a per-IP limit), is rate limited (429 `rate_limited`) and stops when today's spend (UTC day, from real token usage saved in `claude_usage`, Flyway V11) reaches `app.claude.daily-budget-usd` (default $1; 503 `daily_limit_reached`). Every Claude call goes through `limits/ClaudeGate`. **Sentence prompt v12 (TASK-114.1, doc-4):** text in another language is no longer a 422 (only code and gibberish are): Claude returns `sourceLang`, `english` (the natural English version), `wordMatch` (the English headword for one word, phrasal verb or idiom: "buồn" gives "sad"), then `summary`, `better`, `betterWhy`; `explanation` gets `english`, `sourceLang`, `wordMatch` as its first fields (left out for English); the English part is cached under the key of the English version and a small table `sentence_source_alias` (Flyway V33) maps the typed text to it; `app.claude.sentence-prompt-version=v13` (and `PromptVersions.sentence` in the iOS app). **Prompt v13 (TASK-114.6):** `sourceLang` `name` (only a person's name) gives a 422 with code `a_name`, `none` a 422 with code `not_a_word`; the messages are in `NotEnglishException`. **Sentence prompt v10 (TASK-106.6, doc-4):** Claude writes only the English part, cached once without a language; `explanation.translation` is filled from `line_translation` (`POST /api/translate-lines`, TASK-106.2) or is `""` (never null) for a guest, `cachedOnly` or a failed line call; Flyway V29 seeds the cached Vietnamese translations as lines. **Liked items (TASK-93.1, doc-17):** `GET/PUT/DELETE /api/liked` keeps the words and sentences a signed-in user stars (`liked_item`, Flyway V23, deleted with the account; a guest gets 401 `sign_in_required`; no Claude call). **Sync and settings (TASK-93.3, `history/`, doc-22):** `POST /api/sync` (`{since, ops[≤200]}` → `{changes:{history,liked}, cursor}`, last-write-wins by the client time, tombstones for removes and clear-all; `history_item`, new columns `at`/`deleted`/`change_seq`/`chip` on `liked_item`, `user_settings`, sequence `sync_change_seq`, Flyway V32; history capped at 1000 per user); `GET/PUT /api/me/settings` (`targetLanguage`, `showTranslation`, `syncHistory`; off deletes server history); `GET /api/me` also gives sign-in method, member-since, history and liked counts and AI use in the last 24 hours with the daily limit. **Language lines (TASK-106.2, `lines/`, doc-5):** `POST /api/translate-lines` (`{targetLang, texts[1-20]}`, not `en`) gives one short natural line per English text in the user's language from the shared table `line_translation` (Flyway V27, unique on text hash + language + `app.claude.line-prompt-version`); all misses of a request are one Claude call through `ClaudeGate` that returns the line in all 7 languages and saves every one (TASK-106.7; optional `headwords` (same length as `texts`, else 400 `invalid_headwords`) add a translated headword per sense, saved in the same table with `prompt_version` `headword-v1` (`app.claude.headword-prompt-version`) and asked in the same single call, TASK-106.8; usage `Feature.LINE`, counts toward the users' budget); `?cachedOnly=true` never calls Claude and returns `translation: null` for a miss. The iOS sign-in screen is built (TASK-70). **Prefill (TASK-83.1, `prefill/`, doc-18):** a queue (`prefill_item`, Flyway V17) of words and phrases that a night job (`PREFILL_CRON`, UTC, empty = off; it answers only the sources in `PREFILL_CRON_SOURCES`, default `sentence-words` = what users typed) and `POST /api/admin/prefill/run?maxUsd=&limit=&source=` (TASK-83.12, repeatable `source`, none = all) answer through the same `WordService` / `TranslationService` as users, so the shared cache is full before anyone asks. It has no user: `ClaudeGate` checks the run cap (`app.prefill.max-usd-per-run`, default $0.50) instead of sign-in and the users' budget, and its calls are saved as feature `PREFILL`, which the users' $1 budget leaves out. `GET /api/admin/prefill` shows the queue and the spend. **While typing (TASK-83.4, doc-4, doc-5):** `?cachedOnly=true` on `GET /api/words/{word}` and both sentence endpoints answers only from the bundle or the cache, else 404 `not_cached`, and never reaches `ClaudeGate`; word answers send `Cache-Control` (bundled 1 day, cached 1 hour); `GET /api/suggest?q=<prefix>&lang=` (`suggest/`) gives up to 8 bundled words, cached words and cached phrases that start with the prefix (prefix indexes, Flyway V19). **Prefetch while typing (TASK-83.5, doc-4, doc-5):** the app opens the backend connection at launch (`GET /actuator/health`) and, 400 ms after the user stops typing, asks only the cached-only endpoints for the current word, phrase or sentence and keeps a hit in the phone cache (`TranslationStore.schedulePrefetch`); no UI, no Claude call, no sign-in sheet, and History is written only on submit. **Phrases (TASK-83.10, doc-5):** `GET /api/words/{phrase}` (2-6 words, "give up") is answered only from `word_lookup` (404 `not_cached` on a miss, never Claude); the app (`CacheKeys.phraseQuery`) asks it with `cachedOnly=true` before the sentence path and shows a hit as a word card. **Admin Sources (TASK-108, `sources/`, doc-13):** `POST /api/admin/sources` (multipart, 5 MB), `GET /api/admin/sources/{id}` and `POST /api/admin/sources/{id}/queue` find the new words and phrases of a book with no LLM call (Flyway V28 `source_upload`; `prefill_item.source` is 110 characters) and queue the picked ones. **Admin AI picture (TASK-91, `aipicture/`, doc-15):** `GET/POST /api/admin/words/{id}/senses/{n}/media/ai-prompt[/scene]` and `.../ai-picture` give an editable image prompt (newest `media-ai` scene, else a template; the wand asks Claude Sonnet 5.5, `ADMIN` usage, $1 a day cap) and run a background job (one worker, `ai_picture_job`, Flyway V21) that draws it with the **Codex CLI** inside the backend image, signed in with the developer's ChatGPT `auth.json` (`AI_PICTURES_ENABLED`, default off; clean environment; 30 pictures a day; doc-11 section 12). The picture replaces the sense's picture like an upload and goes to "Media to review". |
| `pipeline/` | Python 3.12, uv, Claude Sonnet 5.5, OpenAI GPT Image mini | **Every Claude call goes through `llm.py` (TASK-111):** with `CLAUDE_BASE_URL` + `CLAUDE_AUTH_TOKEN` in `pipeline/.env` it uses the STEYG gateway like the backend (model: the step's env, then `CLAUDE_MODEL`, then `deepseek-v4.1-flash`; the schema goes in the prompt; `collection batch` is blocked, Batches are Anthropic only), else the Anthropic API with `ANTHROPIC_API_KEY`. Generates the NGSL words (3 levelled examples per sense, form types via lemminflect) into `data/pipeline.db`. `topics` (TASK-61) finds everyday concrete words NGSL misses (apple, giraffe) by topic from Open English WordNet + wordfreq, and a Claude Haiku 5.5 judge keeps or drops them (`topic_words` table). `import-to-postgres` copies the bundled `dictionary.sqlite` into the server Postgres once; `export` (needs `DATABASE_URL` in `pipeline/.env`, read-only) builds the `dictionary.sqlite` and `media/` folder bundled in the app from Postgres, see doc-6. `media-check` (TASK-78) has Claude Haiku mark wrong sense pictures `needs_ai`; `media-generate` (TASK-53, `OPENAI_API_KEY`) makes an AI picture for each (`gpt-image-1-mini`, $5 cap per run, `media_generation` table, Flyway V14), then `--link` after rsync, see doc-15. `media-ai` (TASK-82) is the way to give **every** sense an AI picture: Claude Sonnet 5.5 writes a scene, the local **Codex CLI** (`codex exec`, the developer's ChatGPT plan, about 1 minute a picture, no per-picture cost) draws it, Claude Haiku 5.5 checks it with a blind guess (open guess, then multiple choice, up to 3 tries; `--max-cost` is the Claude cap, default $5; Flyway V16 adds scene and guess columns to `media_generation`); `--link` after rsync replaces any picture and keeps the old media row, see doc-15. `prefill collect --source words|phrases|sentences` (TASK-83.2, no paid call) queues the common words not bundled (SCOWL-70 minus the bundled dictionary and kept topic words, lemmas, wordfreq Zipf >= 3.5), WordNet phrasal verbs and idioms, and (TASK-83.11) about 2,500 everyday lines written by hand in `pipeline/data/common_sentences.tsv` ("Looks good.", common replies first; `--dry-run` prices them at the `deepseek-v4.1-flash` rates in `application.properties`) into the backend `prefill_item` table for the night job; `collect ... --now` and `prefill run --source <label> [--max-usd]` (TASK-83.12; admin login from `ADMIN_API_URL` / `ADMIN_EMAIL` / `ADMIN_PASSWORD` in `pipeline/.env`) start a server run at once for what the developer queued; `prefill report` counts the queue and prices the pending rows, see doc-6. **Local collection (TASK-83.9, `collection.py`, doc-18):** `collection collect` fills a `collection` table in `pipeline.db` (no paid call) with common words not bundled, the pending topic and needs_review words, WordNet phrasal verbs and idioms, and the collocations of the bundled usage items; `collection write` has the local **Codex CLI** (ChatGPT plan, no per-call cost) write each one with the backend word prompt (read from `ClaudeService.java`) and the backend checks; `collection batch submit/collect` does the same with Claude Haiku 5.5 through the Message Batches API (half price, `collection_batch.py`); `collection compare` makes a Codex-next-to-Claude HTML page; `collection push --yes` copies done words into the server cache `word_lookup` (never over a Claude row). **Language lines (TASK-106.5, `lines.py`, doc-18):** `lines collect` (read-only Postgres, no paid call) fills a `lines` table in `pipeline.db` with every bundled and backend-word simple definition and every cached sentence text, once per language (vi, ja, ko, zh, fr, es, de); `lines write` has the local **Codex CLI** write 50 texts of one language per call with the backend `LINE_PROMPT` and checks each line (not empty, not English, script, length); `lines push --yes` inserts the good ones into the server `line_translation` (source `codex`, never over an existing row), the key being the same sha256 of the normalized text as `LineTranslationService`; `lines report` counts and gives the time left. `source-lists` (TASK-108, no paid call) writes `zipf-en.tsv` and `phrases-en.tsv` (wordfreq Zipf scores, WordNet phrasal verbs and idioms) into the backend resources for the admin Sources page, see doc-6. |
| `admin/` | React, Vite, TypeScript, Refine, shadcn/ui (Tailwind) | The admin CMS at `admin.saynata.com` (F5): sign in, then review, edit, mark reviewed and regenerate words and sentences through `/api/admin`, and draw an AI picture for a sense from a dialog (TASK-91). **Users (TASK-105):** a People section lists app accounts with sign-in methods, last seen and Claude usage per user (`claude_usage.user_id`, counted from the release day), and can block (no new Claude call, 403 `account_blocked` from `ClaudeGate`; cached answers still work) or delete an account (same as deleting it in the app); `/api/admin/users`, Flyway V31. **Sources (TASK-108, doc-13, doc-18):** upload a book (`.txt` or `.md`, 5 MB) with a title, see the words and phrases that are not bundled, cached or queued (names skipped, no LLM call, the text is never stored) and add the picked ones to the prefill queue with source `book:<title>`; the lists come from `uv run pipeline source-lists`. Builds to static files (`npm run build`); tests: `cd admin && npm test`. |
| `extension/` | Chromium Manifest V3, TypeScript, Vite, Vitest | The browser extension (Brave, Chrome; TASK-86, doc-19): select English on any page, a small teal button with the two-cat logo appears, and a card shows the simple English first, words next, the target language last and closed. Also a right-click item and Alt+Shift+S. One word calls `GET /api/words/{word}`, more calls `POST /api/translations/stream`. Every call goes through the service worker (`host_permissions`, so no backend CORS change). Build: `cd extension && npm run build`, then load `extension/dist` unpacked. Tests: `npm test`. |
| `web/` | Next.js 16 (App Router), TypeScript, Tailwind 4, GSAP, Vitest | The website for learners (TASK-102, doc-23). The homepage (TASK-102.1), **`/download`** (TASK-102.9: iPhone, Mac and extension cards from one config file `lib/downloads.ts`, a QR code made with the `qrcode` package; doc-23) and **sign-in** (TASK-102, doc-17): `/sign-in` and `/sign-up` are one form, the Apple and Google pills, then the 6-digit email code (no emailed link, it is app-only); the account menu sits in the header; the session is in localStorage (`lib/auth.ts`, one shared refresh); a signed-in user gets new Claude calls; a cat room from the same paid pack sits left of the form, hidden under 760px. The homepage is one composer card with a Mochi cat on its edge (one paid sprite sheet per visit, served by Caddy at `/cats/` from `/var/lib/saynata/web-cats`, uploaded with `scripts/upload-web-cats.sh`, never in git; our own pixel cat when missing), suggestions from `GET /api/suggest`, and the word or sentence result below; the query is in the address (`/?q=`). The API client is a copy of `extension/src/shared/`. `/api` is same-origin (a rewrite in `next.config.ts` to `SAYNATA_API_ORIGIN`, default `https://api.saynata.com`), because the backend has no CORS setup. GSAP runs only with `prefers-reduced-motion: no-preference` (`lib/motion.ts`). Run: `cd web && npm run dev`. Tests: `cd web && npm test`; build: `npm run build`. **Deploy (TASK-102.2, doc-23, doc-11 section 14):** `output: "standalone"`; the `deploy-web` job in `deploy.yml` builds on GitHub, copies the server to `web/dist` on the VPS and `web/scripts/deploy-web.sh` runs it as the `web` service (`node:22-alpine`, `127.0.0.1:3001`) in `docker-compose.prod.yml`; Caddy sends `saynata.com/api/*` to the backend and the rest to it (Caddy block and DNS by hand). **Domain (TASK-104, doc-11 section 15):** the product domain is `saynata.com` (`scripts/dns.sh` sets the Cloudflare DNS, token in git-ignored `scripts/.env`); `loffy.me` stays as an alias in Caddy, in the admin CORS origins and in the extension `host_permissions` for one release, and `EMAIL_FROM` stays on it until saynata.com is verified in Resend. |
